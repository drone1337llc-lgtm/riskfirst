The original bot was built on a wrong assumption

An adversarial review found the crypto-only PPO entry was (a) a requirements mismatch for an options/equities/MCP hackathon, and (b) validating itself on nothing out-of-sample.

Mismatch

Crypto-only lane vs an options + equities + MCP/CLI track.

No OOS validation

Train metrics ≠ live. A champion/challenger loop with no out-of-sample gate promotes noise.

Train ≠ live

3% simulated commission on a paper market where commission is 0 → the policy learned to hug cash.

So we fixed the process before adding features — and rebuilt the submission around the options + equities agent with an MCP tool surface.

The hard gate

Walk-forward out-of-sample validation

Crypto lane stays only if OOS Sharpe is positive net. 75/25 train/eval windows, 4 folds, ~300k timesteps, evaluated on data the policy never saw.

The earlier expanding-train variant showed 2/4 negative folds; the spec-compliant 75/25 run is the canonical verdict. High variance → crypto stays a secondary lane, never the headline.

Why it's different

A portfolio-operations stack, not a single strategy

Champion / challenger promote loop

Promote on OOS, never train loss. The walk-forward gate vetoes strategy changes that only look good in-sample.

Options overlay that hedges

Defined-risk income layer — the wheel both generates and protects, rather than pure long-beta.

Circuit breaker stops the bleeding

Hard risk rail enforced at the book level, independent of the signal layer.

Honest validation

Gate results are published as-is — including the noisy folds. No cherry-picked windows.

The story is process + risk rails + honest validation — the thing most hackathon entries skip.
